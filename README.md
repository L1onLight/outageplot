# svitlobot_plot

Telegram-бот, який стежить за графіком відключень світла [ДТЕК КЕМ](https://www.dtek-kem.com.ua/ua/shutdowns)
для конкретної адреси й надсилає його в чат картинкою з підписом.

## Функціонал

### Отримання графіка
- Відкриває сайт ДТЕК у headless Chromium (Playwright) і робить той самий AJAX-запит, що й сторінка,
  тому отримує актуальні дані з CSRF-токеном.
- Визначає всі лінії (черги, `sub_type_reason`), до яких підключений будинок — їх може бути кілька.
- Бере графік на сьогодні й на завтра (якщо його вже опублікували).
- Якщо будинок не знайдено, у помилці показує список доступних номерів на вулиці.

### Картинка
- Таблиця по годинах (00–24) для кожної лінії, окремо блоки «Сьогодні» і «Завтра».
- Стани години: світло є, світла немає, можливе відключення — зокрема для половини години
  (перші / другі 30 хв).
- Кожна лінія має свій колір і підпис з назвою черги.
- Червона риска поточного часу з підписом під таблицею; поточна година в шапці підсвічена
  й виділена червоним. Лише в блоці «Сьогодні» і лише якщо дата графіка збігається з поточною.
- Якщо графік на завтра ще не опубліковано — відповідна заглушка.
- Легенда, час оновлення від ДТЕК і поточний час за Києвом.

### Повідомлення в Telegram
- Перший запуск за добу — нове повідомлення з картинкою й текстовим підписом
  (інтервали відключень по кожній лінії). У підписі лише точні відключення —
  «можливі» видно тільки на картинці.
- Кожен запуск **редагує те саме повідомлення**: картинка перемальовується з актуальною
  позначкою поточного часу. Якщо графік або набір ліній змінився — у підписі з'являється
  «🔄 Графік оновився о HH:MM» (якщо змінились лінії — з приміткою «змінились лінії»)
  і лишається до наступної зміни (окремі повідомлення не надсилаються).
- Якщо повідомлення видалили чи його вже не можна редагувати — надсилається нове.
- Порівняння йде за хешем лише змістовної частини графіка, тож зміна порядку ліній не вважається оновленням.

### Поточні відключення (аварійні роботи тощо)
ДТЕК для адреси віддає поточний стан: причину, час початку й орієнтовний час відновлення.
Головне правило — не спамити підписників:
- У підписі графіка зверху з'являється рядок «⚡ Зараз світла немає …» — для будь-якого
  поточного відключення, зокрема планового. Окремого сповіщення про це немає.
- Для **позапланових** відключень (причина не містить «графік» / «стабілізаційн») —
  **одне** окреме повідомлення на подію. Далі воно лише тихо редагується. Якщо під час події
  ДТЕК змінить причину чи час початку або переведе її в планове відключення — це та сама подія.
- Перенесення орієнтовного часу — тихе редагування з історією (`~~06:15~~ ~~07:00~~ 10:00`,
  закреслені дві попередні обіцянки) і часом перенесення.
- Пінг (відповідь на повідомлення) — лише коли попередній обіцяний час **уже минув**, а ДТЕК
  змінив його; не частіше ніж раз на годину. Попередній пінг видаляється, останній — коли
  світло відновили.
- Коли обіцяний час минув без оновлення — у повідомленні з'являється «⏳ … чекаємо оновлення».
- «✅ Світло відновлено» — тим самим повідомленням, коли ДТЕК **дві перевірки поспіль** не показує
  за адресою жодного відключення (захист від мерехтіння відповіді сайту). Час відновлення —
  час першої з цих перевірок.
- Якщо повідомлення про відключення видалили, поки подія триває, — надсилається нове.
- Застарілі дані (час оновлення ДТЕК старший за збережений) ігноруються.

### Тиша вночі
З 23:00 до 08:00 за Києвом усі нові повідомлення (графік на новий день, повідомлення
про відключення, пінги) надсилаються без звуку.

### Захист від «поганих» відповідей сайту
Вчорашні дані (кеш сайту) пропускаються завжди, крім `--force`.

Під час редагування повідомлення з графіком відповідь також ігнорується, якщо:
- немає ліній або графіка на сьогодні;
- зник графік на завтра, який раніше вже був;
- час оновлення ДТЕК старший за збережений.

Перше повідомлення за добу й `--force` надсилаються з тим, що віддав сайт.

### Надійність
- Стан (`state.json`) записується атомарно.
- Файловий лок (`.lock`) не дає двом екземплярам працювати одночасно
  (у GitHub Actions те саме забезпечує `concurrency`).
- Тимчасові помилки Telegram (мережа, 429, 5xx) не ламають стан — повтор на наступному запуску,
  зокрема для пінгів і «світло відновлено».
- Помилка з повідомленням про відключення не блокує оновлення графіка.

## Налаштування

Потрібні Python 3.13+ і [uv](https://docs.astral.sh/uv/).

```sh
uv sync
uv run playwright install chromium
cp .env.example .env
```

Заповніть `.env` у корені проєкту:

```dotenv
TELEGRAM_BOT_TOKEN=123456:ABC...
TELEGRAM_CHAT_ID=-100...
STREET=вул. Хрещатик
HOUSE=1
```

Назви вулиці й будинку мають збігатися з тими, що на сайті ДТЕК.

Необовʼязково: `FONT` / `FONT_BOLD` — шляхи до TTF-шрифтів для картинки
(за замовчуванням шукаються Noto Sans або DejaVu Sans).

## Запуск

```sh
uv run python bot.py               # одна перевірка
uv run python bot.py --loop        # постійно, перевірка кожні 30 хв
uv run python bot.py --force       # примусово надіслати нове повідомлення
uv run python bot.py --preview out.png  # лише зберегти картинку й вивести підпис, без Telegram
```

`--preview` нічого не надсилає, але `.env` однаково має містити всі змінні. Крім підпису графіка
друкує текст повідомлення про позапланове відключення, якщо воно є.

### GitHub Actions

Workflow `.github/workflows/svitlobot.yml` запускає бота в хмарі:
- `repository_dispatch` (type `check`) — основний тригер кожні 30 хв із зовнішнього cron
  (наприклад, cron-job.org), бо вбудований cron GitHub запізнюється;
- `schedule` — запасний, щогодини (заодно не дає GitHub вимкнути workflow);
- `workflow_dispatch` — ручний запуск з опцією `force`.

Зовнішній cron має кожні 30 хв робити такий запит:

```http
POST https://api.github.com/repos/<owner>/<repo>/dispatches
Authorization: Bearer <token>
Accept: application/vnd.github+json

{"event_type": "check"}
```

`<token>` — fine-grained personal access token лише на цей репозиторій з правом
**Contents: Read and write**. Успішна відповідь — `204 No Content`.

Секрети репозиторію: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `STREET`, `HOUSE`.
Їх можна задати з локального `.env` одним скриптом (потрібен залогінений [gh](https://cli.github.com/)):

```sh
./scripts/setup_gh_secrets.py      # покаже команди й попросить підтвердження
./scripts/setup_gh_secrets.py -y   # без підтвердження
```

Скрипт друкує команди `gh secret set ...` перед виконанням; токен бота в них обрізаний до `BOT_ID:...`.
Стан зберігається в окремій гілці `artifacts` (один коміт без історії, перезаписується лише при змінах).

## Розробка

```sh
uv run pre-commit install
uv run pre-commit run --all-files
```

Pre-commit хуки:
- gitleaks і `detect-private-key` — токени й приватні ключі;
- `scripts/check_env_leaks.py` — значення з `.env` (адреса, chat id тощо) не потрапили в жоден файл;
- заборона комітити `.env`, `state.json`, `state.tmp`, `.lock`;
- ruff (lint + format);
- стандартні перевірки: великі файли, маркери конфліктів злиття, валідність YAML,
  пробіли в кінці рядків, порожній рядок у кінці файлу.

## Структура

| Файл | Призначення |
|---|---|
| `bot.py` | Логіка перевірки, стан, Telegram API, CLI |
| `dtek.py` | Отримання графіка з сайту ДТЕК через Playwright |

| `.env.example` | Шаблон `.env` |
